00 · 关键判断
accent 取深松绿，不取靛蓝
A 小样里凸起的记一笔按钮和「全部交易」链接已经是绿的，就沿用。B 的单一靛蓝在 A 上会和「转账」的灰蓝在同一张表里打架，所以不取。
accent 绿 ≠ 收入绿，靠明度和用法拉开
accent 是深松绿 #1C4A3A（只做实心填充、链接、焦点环），kind.income 是更亮的草绿 #12693F（只做数字与色块）。两者从不以同一种形态出现，金额列不会被强调色抢走。
深色借 C，不是把 A 反相
暖纸直接反相会得到发绿的脏灰。深色走 C 的暖炭底（#16140F 系，偏土不偏蓝）。但 accent 在深色翻成纸白而不是 C 的琥珀 —— 琥珀留给「退款」。
B 的贡献是刻度和图标，不是网格
4 的倍数间距、20px 网格 1.5px 描边的线性图标集全部采纳。但 A 的发丝线分栏保留 —— 不做圆角卡片堆叠，只有 Sheet / Dialog / Toast 是浮层。

规则
描边恒定 1.5px，不随字号变；24px 场景用 scale 而非换描边。端点圆头、拐角圆角 0.5。方向性图标（收支箭头）统一 45° 或正交，不用任意角度。图标颜色永远继承文字色，语义色只在 Badge / 色块上出现 —— 表格里一列彩色图标会盖掉金额。

A 一条发丝线 · 同宽对齐（保留）
你明确说了不要「把所有东西都做成卡片」，我同意。三个账户是同一维度的三行，卡片把它们拆成三个独立对象，金额也不再共享右对齐基线 —— 对账时最要紧的恰恰是金额能竖着扫下来。
净结果：颜色、版式、字体、层次全部来自 A；间距刻度、图标集、方向性箭头来自 B；深色底色和明度关系来自 C。三个方向没有并排出三套 token —— 你说了倾向 A，出三套只会把选择成本推回给你。要看完整的 B 或 C 版 token，说一声我单独出。
