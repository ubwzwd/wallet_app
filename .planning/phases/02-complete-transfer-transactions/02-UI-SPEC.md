## Interaction Contract

### Two-Step Wizard (new)

The wizard lives inside the existing `TransactionFormScreen` component using a `step` state variable (`1 | 2`). No routing or nested modals.

**Step 1 layout (top to bottom within Card):**
1. Step indicator: `sectionLabel` style — "Step 1 of 2 — Select Accounts"
2. Finance Source (FROM): existing source picker field, labeled "From"
3. Destination (TO): new source picker field using Modal+FlatList pattern, labeled "To"
   - Web: `<select>` element matching existing picker style (`pickerContainer` + `picker`)
   - Native: `TouchableOpacity` trigger + Modal + FlatList (exact clone of currency picker)
4. Navigation row: "Cancel" (secondary) left, "Next →" (primary) right

**Step 2 layout (top to bottom within Card):**
1. Step indicator: `sectionLabel` style — "Step 2 of 2 — Enter Amount"
2. Amount Input
3. Currency picker (existing)
4. Date Input
5. Description Input (optional)
6. Merchant Input (optional)
7. Tags Input (optional)
8. Navigation row: "← Back" (secondary) left, "Create Transfer" (primary) right

**Edit mode for transfer transactions** (D-10, D-11):
When `isEditing && transaction.transfer_pair_id`: show a single-step form with Amount, Date, Description, Merchant, Tags only. Source and currency fields are read-only. A static note reads: "Source and currency cannot be changed on an existing transfer." (12px, `#6b7280`, `hint` style). Submit button title: "Update Transfer".

### Loading State

Single `ActivityIndicator` (via `Button loading={true}`) covering both sequential POST calls. The "Create Transfer" button switches to `loading={true}` immediately when tapped and stays in loading state until both POSTs complete or either fails. "← Back" is disabled during load.

### Partial Failure State

On first POST success + second POST failure after delete attempt: native `Alert.alert` (or `window.alert` on web) with title "Transfer Error" and message "Transfer partially created. One transaction may exist in your account — please check your transactions and delete manually if needed." (D-08 from CONTEXT.md). Form remains open so user can retry.

### Destination Source Exclusion

The TO picker list excludes the currently selected FROM source (D-05). If only one source exists when Transfer tab is tapped: Transfer button remains disabled with hint text "Add another finance source to enable transfers." (D-05, 12px, `#6b7280`, `hint` style).

### Transfer Tab Enable

Remove `disabled` prop from the Transfer button (lines 203–214). Remove the "Transfer support coming soon" hint text. For single-source users only, show the exclusion hint instead.
