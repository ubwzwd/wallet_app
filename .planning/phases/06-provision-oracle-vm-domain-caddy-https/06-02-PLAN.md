Verifier conventions (sourced from smoke.sh and verify-pwa.mjs):
- Shebang: `#!/usr/bin/env bash`
- Strict mode: `set -euo pipefail`
- Repo-root resolution: `REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"`
- Stdout cadence: `echo "==> <step name>"` for each check entry
- Stderr on failure: `echo "FAIL: <reason>"; exit 1` — inlined as `|| { echo "FAIL: <reason>"; exit 1; }`
- End-of-script success marker: `echo "OK: Phase 6 verify green"`
- Mode arg: `MODE="${1:-quick}"` (default quick)
- Permissions: `chmod 755` (smoke.sh / env-coverage.sh are both rwxr-xr-x)

SC1–SC5 verification recipe (from 06-VALIDATION.md §Per-Requirement Verification Map):
| Req | Quick (local) | Full (against VM) |
|-----|---------------|-------------------|
| Caddyfile syntax | `docker run --rm -v "$PWD/infra/Caddyfile:/etc/caddy/Caddyfile:ro" caddy:alpine caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile` | (same) |
| .env.example schema | grep CADDY_ACME_CA + CHANGE_ME_YOUR_DOMAIN + 7 keys present | (same) |
| DOMAIN-01 DNS | (n/a local) | `[ "$(dig @1.1.1.1 "$DOMAIN" +short \| head -1)" = "$EXPECTED_IP" ]` |
| DOMAIN-02 LE prod | (n/a local) | `curl -vI "https://$DOMAIN/" 2>&1 \| grep -i 'issuer' \| grep -v -i STAGING` |
| DOMAIN-03 HSTS | (n/a local) | `curl -sI "https://$DOMAIN/" \| grep -qi '^strict-transport-security:.*max-age=31536000.*includeSubDomains$'` |

       g. `echo "==> compose: prod compose lints clean"` — `docker compose -f "$REPO_ROOT/infra/docker-compose.prod.yml" config -q || { echo "FAIL: docker compose config"; exit 1; }`.

       After quick checks, if MODE=quick, print `echo "OK: Phase 6 quick verify green"` and `exit 0`.

    6. **FULL mode block** (gated on `if [ "$MODE" = "full" ]; then`). Eight assertions:
       a. `echo "==> dns: $DOMAIN -> $VM_IP via 1.1.1.1 (DOMAIN-01)"` — `[ "$(dig @1.1.1.1 "$DOMAIN" +short | head -1)" = "$VM_IP" ] || { echo "FAIL: DNS does not resolve to $VM_IP"; exit 1; }`.
       b. `echo "==> https: $DOMAIN returns HTTP/2 200 (SC1)"` — `curl -sI "https://$DOMAIN/" | grep -qi '^HTTP/2 200' || { echo "FAIL: https://$DOMAIN/ did not return 200"; exit 1; }`.
       c. `echo "==> tls: LE production cert (not staging) — DOMAIN-02 / D-05"` — capture `curl -vI "https://$DOMAIN/" 2>&1` to a temp string, then assert the issuer line contains `Let's Encrypt` AND does NOT contain `STAGING` or `Fake LE Root` or `Pretend Pear`. Implementation: `out=$(curl -vI "https://$DOMAIN/" 2>&1); echo "$out" | grep -qi 'issuer.*Let.s Encrypt' || { echo "FAIL: cert issuer is not Let's Encrypt"; exit 1; }; echo "$out" | grep -qiE 'STAGING|Fake LE|Pretend Pear' && { echo "FAIL: cert is from STAGING — D-05 flip not done"; exit 1; }; true`.
       d. `echo "==> hsts: response header present (DOMAIN-03)"` — `curl -sI "https://$DOMAIN/" | grep -qi '^strict-transport-security:.*max-age=31536000.*includeSubDomains' || { echo "FAIL: HSTS header missing on response"; exit 1; }`.
       e. `echo "==> ports: nmap shows only 23333/80/443 reachable on $VM_IP (SEC-02 / D-15)"` — run `scan=$(nmap -Pn -p 22,23333,80,443 "$VM_IP" -oG -)`. Assert: `echo "$scan" | grep -qE '22/(closed|filtered)' || { echo "FAIL: port 22 unexpectedly reachable"; exit 1; }`. Assert open ports: `echo "$scan" | grep -qE '23333/open' || { echo "FAIL: port 23333 not open"; exit 1; }`, same for 80, 443.
       f. `echo "==> health: /health returns 200 and JSON status (OPS-01)"` — `curl -sf "https://$DOMAIN/health" | grep -q '"status"' || { echo "FAIL: /health did not return JSON status"; exit 1; }`.
       g. `echo "==> health: /health response time < 500ms (OPS-01)"` — `t=$(curl -sf -o /dev/null -w '%{time_total}' "https://$DOMAIN/health"); awk -v t="$t" 'BEGIN { exit (t < 0.5) ? 0 : 1 }' || { echo "FAIL: /health took ${t}s (>500ms)"; exit 1; }`. Note: the 500ms threshold accounts for network RTT from operator laptop; ROADMAP SC4's <100ms is the LAN-local measurement when the operator is SSH'd into the VM and curls the loopback. The script measures the external path; if the operator wants the strict 100ms LAN measurement, they run it from inside the VM (documented in RUNBOOK).
       h. `echo "==> evidence: infra/runbook-evidence/uptime-alert.png exists (OPS-02 / SC5)"` — `test -s "$REPO_ROOT/infra/runbook-evidence/uptime-alert.png" || { echo "FAIL: SC5 evidence screenshot missing — operator must complete UptimeRobot drill per RUNBOOK §15"; exit 1; }`.

    8. **Permissions**: make the file executable. (The execute task will need to chmod +x; document this in the task acceptance criteria.)
