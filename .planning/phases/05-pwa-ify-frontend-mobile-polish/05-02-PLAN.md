  <action>
    **Part A — Author the script.** Create `frontend/scripts/generate-icons.mjs` as an ES-module Node script (shebang `#!/usr/bin/env node`). Import sharp: `import sharp from 'sharp';` plus `node:fs`, `node:path`, `node:url`. Resolve paths relative to the script: `const SCRIPT_DIR = path.dirname(new URL(import.meta.url).pathname);` and `const FRONTEND = path.resolve(SCRIPT_DIR, '..');` so the script can be invoked from any cwd.

    The script logic:
    1. Read the design source: `const sourceBuf = fs.readFileSync(path.join(FRONTEND, 'assets/adaptive-icon.png'));`.
    2. Define the background color: `const BG = { r: 0x0e, g: 0xa5, b: 0xe9, alpha: 1 };` (the `#0ea5e9` accent per D-11).
    3. Define an emitter helper `async function emit(outName, canvasSize, foregroundScale) { ... }`:
       - Compute `fgSize = Math.round(canvasSize * foregroundScale)`.
       - Resize the source to a centered `fgSize × fgSize` PNG buffer using `sharp(sourceBuf).resize(fgSize, fgSize, { fit: 'contain', background: BG }).png().toBuffer()`.
       - Composite that foreground onto a `canvasSize × canvasSize` solid-BG canvas: `await sharp({ create: { width: canvasSize, height: canvasSize, channels: 4, background: BG } }).composite([{ input: fgBuf, gravity: 'center' }]).png().toFile(path.join(FRONTEND, 'public', outName));`
       - Log `==> generate-icons: wrote frontend/public/${outName}` to stdout.
    4. Run four emissions:
       - `emit('192.png', 192, 1.0)` — foreground fills the canvas edge-to-edge (standard, purpose: any).
       - `emit('512.png', 512, 1.0)` — same as 192 but 512×512.
       - `emit('512-maskable.png', 512, 0.8)` — foreground rescaled to 80% (410×410) centered on the full 512 canvas, leaving a 51px border of `#0ea5e9` so masks/rounded crops don't clip the foreground (web.dev maskable-icons safe-zone spec).
       - `emit('apple-touch-icon.png', 180, 1.0)` — 180×180 for iOS home-screen.
    5. Top-level `await` (the script is an ESM module — top-level await works) the four emits sequentially. Wrap in a try/catch that logs `FAIL: generate-icons — <err.message>` to stderr and `process.exit(1)` on any error.

    **Part B — Run the script to produce the PNGs.** From `frontend/`, execute `node scripts/generate-icons.mjs`. Confirm the four PNGs land at the expected paths under `frontend/public/` and that each is a valid PNG (magic bytes `89 50 4E 47 0D 0A 1A 0A`) with the expected dimensions (use a tiny sharp metadata check or `node -e` width/height parse from the IHDR chunk at byte offset 16–24).

    **Part C — Author favicon.ico.** Produce a multi-resolution ICO containing at least a 32×32 frame derived from the same composition. The script may extend `generate-icons.mjs` to also emit favicon.ico (sharp does not emit ICO natively — either use `sharp` to produce a 32×32 PNG buffer and then a tiny ICO wrapper, OR have the script invoke a one-off `convert` from ImageMagick if available, OR write a small inline ICO-header builder in Node). Acceptable alternative: keep favicon.ico generation out of the script and instead commit a one-time-generated ICO produced by any standard tool, provided it has valid Windows Icon magic (first 4 bytes `0x00 0x00 0x01 0x00`). Document the chosen approach inline in `generate-icons.mjs` with a comment.

    Do NOT add sharp to `dependencies` — it was installed as a `devDependency` in 05-01 Task 1 per the revised D-10. Do NOT commit any temporary build artifacts beyond the 4 PNGs + favicon.ico + the script itself.
