Per the revised D-07/D-08/D-09 (user spot-check 2026-05-24), the previously planned `<UpdateToast />` sibling render is REMOVED — App.tsx integration is now JUST the SafeAreaProvider wrap + the side-effect import.

Purpose: Per ROADMAP SC-4, `safe-area-inset-top/bottom` padding MUST be applied to header and bottom navigation. Per RESEARCH §Anti-Patterns ("Forgetting SafeAreaProvider"), `useSafeAreaInsets()` silently returns zero without the provider, so the wrap is load-bearing. Per CONTEXT D-09 (revised), the SW side-effect import is wired here (alongside the provider wrap) to keep all App.tsx edits in one plan and to avoid Wave-1 merge conflicts. The `<UpdateToast />` element previously specified in D-09 is no longer mounted — the silent SW takeover via Workbox `skipWaiting + clientsClaim` (preserved per ROADMAP SC-3) replaces the explicit user-opt-in toast.

Output: Two files modified; `useSafeAreaInsets()` now works on web; App boots with the SW registration side-effect imported; no UI surface for SW updates; `verify-touch-targets.mjs --check=screen-safe-area` and `--check=app-safe-area-provider` both PASS.
