<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser ↔ Service Worker | SW intercepts every fetch request on the origin; a misconfigured cache could serve another user's data |
| Service Worker ↔ Cache Storage | CacheFirst entries can persist across user sessions on a shared device |
| Build pipeline ↔ workbox-cli | A compromised Workbox could inject arbitrary JS into the emitted sw.js (mitigated by 05-01's package legitimacy gate) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Tampering / data freshness | Stale-shell trap (user stuck on old client code) | mitigate | `NetworkFirst` on `/index.html` AND `/api/*` (per workbox-config.cjs runtimeCaching entries 1 & 2); `skipWaiting: true` + `clientsClaim: true` so a new SW takes over silently on activation (revised D-07 — no UpdateToast UI; the next navigation or refresh after deploy surfaces the new version because of NetworkFirst on `/index.html`). The registerSW client just logs registration; the SW does all the work. |
| T-05-03-02 | Information Disclosure | Cross-user cache leakage on shared device | accept (partial mitigation) | NetworkFirst on `/api/*` means a fresh login fetches the current user's data when network is reachable.
