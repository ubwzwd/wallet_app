## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tag internal padding (`paddingVertical: 4`) |
| sm | 8px | Button gap between actions, tag container gap |
| md | 16px | Default screen padding, card padding, section padding |
| lg | 24px | Header bottom margin, section breaks |
| xl | 32px | Empty state padding |
| 2xl | 48px | Reserved (not used in this phase) |
| 3xl | 64px | Reserved (not used in this phase) |

**Source:** Extracted from existing StyleSheet values across `TransactionsScreen.tsx`, `FinanceSourcesScreen.tsx`, `Card.tsx`, `Screen.tsx`.

Exceptions:
- **Touch targets:** Minimum 44px height/width on all interactive elements (MOBUI-01 locked requirement). This is an override on `small` Button size (currently `paddingVertical: 8` which produces ~38px height). Buttons must declare `minHeight: 44` and `minWidth: 44` as a platform-level override.
- **Safe area:** `paddingTop` for header uses `safe-area-inset-top` (dynamic, not a fixed token). `paddingBottom` for bottom navigation uses `safe-area-inset-bottom`. These are not fixed spacing tokens.
- **Bottom navigation height:** 56px fixed + safe-area-inset-bottom. The 56px accommodates a 24px icon + sm (8px) padding top/bottom + 8px label.

## Touch Target Enforcement Contract

**Locked by MOBUI-01 (≥44×44 CSS px).**

All interactive elements must satisfy 44px minimum in BOTH dimensions.

| Element | Current Size | Required Fix |
|---------|-------------|--------------|
| Transaction row Edit button (size="small") | ~38px height | Add `minHeight: 44` to `actionButton` style |
| Transaction row Delete button (size="small") | ~38px height | Add `minHeight: 44` to `actionButton` style |
| FinanceSource row Edit button (size="small") | ~38px height | Add `minHeight: 44` to `actionButton` style |
| FinanceSource row Archive button (size="small") | ~38px height | Add `minHeight: 44` to `actionButton` style |
| Modal close button (future modals) | N/A | Declare 44×44 as baseline in any new close button |
| Currency picker rows | ~38px height | Add `minHeight: 44` to picker row TouchableOpacity |
| Tag chips | ~22px height | Tags are display-only (not interactive) in current code — no fix needed unless made tappable |
| Navigation tabs | 48px (paddingVertical: 16 + 16 text) | Already compliant |

**Enforcement mechanism:** Add `minHeight: 44, minWidth: 44` to the `small` size style in `Button.tsx` (currently `paddingVertical: 8, paddingHorizontal: 16`). This is the single-point fix — all small buttons across the app are compliant after this change.

## Service Worker Caching Contract

**Locked by PWA-04 (ROADMAP success criteria 3).**

| Asset type | Strategy | Implementation |
|-----------|----------|---------------|
| JS chunks | Cache-first | Workbox `CacheFirst` with `CacheableResponsePlugin` (status 0, 200) |
| CSS | Cache-first | Workbox `CacheFirst` |
| Fonts | Cache-first | Workbox `CacheFirst` with 30-day expiry |
| Images (PNG/SVG/WEBP) | Cache-first | Workbox `CacheFirst` |
| `/index.html` | Network-first | Workbox `NetworkFirst` — prevents stale-shell trap |
| `/api/*` | Network-first | Workbox `NetworkFirst` — live data always preferred |
| SW activation | Immediate | `skipWaiting()` + `clients.claim()` on `activate` event |

**SW update UX:** When a new SW is waiting, display an unobtrusive toast at bottom of screen: "Update available" with a "Reload" button. On tap: `registration.waiting.postMessage({ type: 'SKIP_WAITING' })` then `window.location.reload()`. This is minimal — no full-screen takeover, no forced reload.

**Offline fallback:** If network-first fetch for `/index.html` fails (offline) and no cached version exists, SW serves a minimal offline.html with the copy from the Copywriting Contract above. If cached `/index.html` exists, serve it. For `/api/*` failures, the app renders the network error state defined in the Copywriting Contract.

**Tooling:** Workbox via `vite-plugin-pwa` (if Expo web export uses Vite) or `workbox-webpack-plugin` (if Metro web bundler). Executor must confirm bundler and select appropriate Workbox integration. The caching strategy above is bundler-agnostic.
