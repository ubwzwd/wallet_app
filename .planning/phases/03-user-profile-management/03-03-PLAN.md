**Part A: Modify client.ts 401 interceptor**

In `frontend/src/api/client.ts`, find the 401 response handler (around lines 48-53). Modify it to preserve the token for GET /auth/me failures:

```typescript
if (status === 401) {
  // Check if this is a status-check call (GET /auth/me)
  const url = error.config?.url || '';
  const method = (error.config?.method || '').toLowerCase();
  
  // Don't clear token on GET /auth/me failures — might be transient
  const isAuthMeGet = url.includes('/auth/me') && method === 'get';
  
  if (!isAuthMeGet) {
    // Real protected resource failed — logout
    await AsyncStorage.removeItem(STORAGE_KEYS.AUTH_TOKEN);
    await AsyncStorage.removeItem(STORAGE_KEYS.USER_DATA);
  }
  
  // Let the error propagate regardless
  return Promise.reject(error);
}
```

**Part B: Modify ProfileScreen onSuccess handler**

In `frontend/src/screens/ProfileScreen.tsx`, find the onSuccess callback (around lines 43-51). Modify it to handle refreshUser failures gracefully:

```typescript
onSuccess: async () => {
  try {
    await refreshUser();
  } catch (error) {
    // Refresh after update might fail due to transient 401
    // But the PATCH succeeded, so user data is updated on server
    // Log the error but don't block UI from proceeding
    console.warn('Refresh after update failed (transient?), proceeding anyway:', error);
  }
  
  const msg = 'Profile updated successfully!';
  if (Platform.OS === 'web') {
    window.alert('Success\n\n' + msg);
  } else {
    Alert.alert('Success', msg);
  }
  
  onBack();
},
```

This prevents a transient 401 from blocking the navigation back to HomeScreen.
