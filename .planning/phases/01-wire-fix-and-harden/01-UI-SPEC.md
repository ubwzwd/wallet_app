# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend changes in Phase 1. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Vertical padding in currency list items |
| sm | 8px | Currency list item gaps, button gaps |
| md | 16px | Currency modal content padding, list item horizontal padding |
| lg | 24px | Header-to-content margins |
| xl | 32px | Empty state padding |

**Source:** Scoped to new Phase 1 work (currency picker modal). All values are multiples of 4 and within the standard set {4, 8, 16, 24, 32, 48, 64}.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Caption | 12px | 400 | 18px (1.5) |
| Label | 14px | 600 | 20px (1.43) |
| Body | 16px | 400 | 24px (1.5) |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (white) | Screen backgrounds, card backgrounds, input backgrounds |
| Secondary (30%) | `#f9fafb` (gray-50), `#f3f4f6` (gray-100), `#e5e7eb` (gray-200) | Summary backgrounds, tag backgrounds, borders, dividers |
| Accent (10%) | `#0ea5e9` (sky-500) | Primary buttons, focused input borders, refresh spinner, currency badge background via `#eff6ff` |
| Destructive | `#ef4444` (red-500) | Delete buttons, error text, negative amounts |

Accent reserved for:
- Primary action buttons (background `#0ea5e9`, text `#ffffff`)
- Secondary button borders and text (`#0ea5e9`)
- Focused input border (`#0ea5e9`)
- Pull-to-refresh spinner color
- Currency badge text highlight (`#0ea5e9` on `#eff6ff` background)

Additional semantic colors (established, not new):
- Success: `#10b981` (emerald-500) -- positive amounts only
- Info: `#1e40af` on `#dbeafe` -- transfer badge, `#1e40af` on `#eff6ff` -- info boxes
- Warning: `#92400e` on `#fef3c7` -- archived badge

**Source:** Extracted from existing `StyleSheet.create` and inline color references. No new colors introduced in Phase 1.

## Currency Picker Modal — Native (New Component)

This is the only new UI element in Phase 1. It replaces the horizontal `ScrollView` of 6 currency buttons with a full-screen modal on native platforms.

### Layout

| Property | Value |
|----------|-------|
| Presentation | Full-screen `Modal` with `animationType="slide"` |
| Background | `#ffffff` (white) |
| Header height | 56px |
| Header background | `#ffffff` with bottom border `#e5e7eb` 1px |
| Header title | "Select Currency" -- fontSize 18px, fontWeight 600, color `#1f2937` |
| Dismiss button | Top-right of header -- "Close" text, color `#0ea5e9`, fontSize 16px, fontWeight 600 |
| List item height | 48px (44px minimum touch target + 4px vertical padding) |
| List item padding | horizontal 16px |
| List item text | "CODE - Full Name" -- fontSize 16px, color `#1f2937` |
| List item code portion | fontWeight 600 |
| List item separator | bottom border `#f3f4f6` 1px |
| Selected item indicator | Background `#eff6ff`, code text color `#0ea5e9` |
| Safe area | Respect `SafeAreaView` on iOS (use existing `Screen` component pattern) |

### Interaction

| Event | Behavior |
|-------|----------|
| Open | Triggered by pressing the currency field (a `TouchableOpacity` displaying current currency code) |
| Select currency | Set currency value, close modal immediately |
| Close | Close modal without changing value |
| Scroll | `FlatList` with default scroll behavior |

### Web Behavior

On web (`Platform.OS === 'web'`): keep the existing horizontal `ScrollView` with currency buttons, populated from the live API fetch instead of the hardcoded array. No modal needed on web.

**Source:** Decision D-08 (web: keep `<select>` or buttons), D-09 (native: Modal + FlatList). Note: TransactionFormScreen currently uses horizontal button row, not `<select>`, for currency. Keep that pattern on web but populate from API. FinanceSourceFormScreen uses the same horizontal button pattern.

## Implementation Notes

### What Changes Visually in Phase 1

1. **Currency picker (both form screens):** 6 hardcoded horizontal buttons replaced by API-populated list. On web: same horizontal button row but with 31+ currencies (scrollable). On native: tapping the currency field opens a full-screen FlatList modal.
2. **Delete confirmation (TransactionsScreen, native only):** Previously no-op on native (missing `else` branch). Now shows native `Alert.alert` dialog before deletion with context-specific labels (branching on isTransfer).
3. **Archive error (FinanceSourcesScreen):** Already has native `Alert.alert` in `onError` based on code inspection. The bug fix (BUG-03) may be about adding it where missing -- verify against `CONCERNS.md` diagnosis.

### What Does NOT Change Visually

- No new screens
- No layout changes
- No color changes
- No typography changes
- No new component variants
- All backend conversion wiring is invisible to the UI (data fields populate automatically in existing response shapes)

### Existing Patterns to Follow

- `Platform.OS` branching: already used in `TransactionsScreen.tsx` and `TransactionFormScreen.tsx`
- `Alert.alert` three-argument form: already used in `FinanceSourcesScreen.tsx` lines 59-70 and `FinanceSourceFormScreen.tsx` mutations
- `useQuery` with `QUERY_KEYS`: already used for transactions and finance sources
- `staleTime: Infinity` for rarely-changing data: recommended for currencies (RESEARCH.md)
